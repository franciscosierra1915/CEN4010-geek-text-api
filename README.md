### Branching Strategy & Git Workflow 
To minimize any code and keep the code stable the following will be considered:

* No Direct Commits to main: The main branch is reserved exclusively for working, stable code that is ready for Sprint Reviews.

* Feature Branch Naming: Every developer will create a isolated branch for their assigned feature. Use the naming convention: feature/feature-name (e.g., feature/profile-management or feature/shopping-cart).

* Pull Requests (PRs): When a user story is complete, open a Pull Request to merge into main. Another team member would be require to review and approve the code before it is merged.

### User Story & Capacity Rules

* Estimation: Work effort will be considered in hour units.
* Sprint Capacity: Each member has a strict maximum allocation of 8 hours of work per 2-week sprint (4 hours per week).
